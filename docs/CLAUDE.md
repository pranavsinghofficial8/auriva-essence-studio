# CLAUDE.md

Auriva is a marketing and storefront site for a premium incense and home-fragrance brand
("from petal to presence"). The design brief lives in `README.md`: editorial, unhurried, luxury
maison (Aesop, Diptyque, COS). **It is front-end only. There is no backend, database or payments.**

> [!IMPORTANT]
> This repo is synced with [Lovable](https://lovable.dev) (see `AGENTS.md`). Never force-push or
> rewrite pushed history. Every commit pushed to `main` shows up in the Lovable editor, so keep
> `main` building.

## Commands

```sh
npm run dev        # vite dev server
npm run build      # production build (nitro, Cloudflare target by default)
npm run build:dev  # development-mode build
npm run preview
npm run lint       # eslint (includes prettier as a rule)
npm run format     # prettier --write .
```

There is no test suite. `bun.lock` is the committed lockfile (Lovable uses bun); `bunfig.toml`
has a 24h minimum-release-age guard, so don't add packages to its exclude list without asking.

## Stack

- **TanStack Start** (SSR React framework) + **TanStack Router** (file-based routing) on **Vite 8**
- **React 19**, **TypeScript** (strict, including `noUncheckedIndexedAccess` and
  `exactOptionalPropertyTypes`)
- **Tailwind CSS v4** (CSS-first config in `src/styles.css`, no `tailwind.config.*`)
- **shadcn/ui** (new-york style, Radix primitives) in `src/components/ui/`
- TanStack Query is wired up in the root route but not used for data yet
- `lucide-react` icons, `zod` / `react-hook-form` available but not used by app code
- Build and deploy via **nitro**, Cloudflare target by default

`vite.config.ts` uses `@lovable.dev/vite-tanstack-config`, which already registers tanstackStart,
React, Tailwind, tsconfig paths, nitro, the `@` alias and `VITE_*` env injection. **Do not add
those plugins again**; pass extra config through `defineConfig({ vite: { ... } })`.

## Key components and data flow

- **`Nav`** (`components/auriva/Nav.tsx`): sticky nav, transparent over the hero, solid ivory once
  scrolled. Pages pass a `threshold` prop (the scroll offset where it turns solid).
- **`Footer`** and **`Logo`**: `Logo` renders `assets/auriva-logo.png` (or `-light.png` with
  `light`, for dark backgrounds) plus the tagline.
- **`HeroSmoke`** (`components/auriva/HeroSmoke.tsx`): WebGL shader drawing smoke that rises
  from the hero photo's wisps. `REGION`/`SOURCE` are in photo units (0–1 across the square
  photo) and stay aligned via `--d` (the photo's rendered size) and the hero's
  `container-type: size`; `SPEED` scales the motion. Alongside it, `.hero-smoke-live` in
  `styles.css` gently warps the photo's own wisps with the `#hero-smoke-warp` SVG filter. Both
  layers are hidden on narrow portrait screens (the photo's smoke is cropped out there) and with
  reduced motion; the shader also pauses when scrolled away. It only fits `hero-lotus.jpg`, so
  retrace `SOURCE` if the hero photo changes.
- **`Reveal` / `useReveal`**: IntersectionObserver fade-in, driven by the `reveal` utility and a
  `data-shown` attribute.
- **Marks**: `marks.tsx` (Aura/Petal/Smoke/Sigil/Bag), `aura-marks.tsx` (`AuraGlyph` per
  `AuraName`, and `AuraMedallion`: the glyph in a thin circle that fills and ripples on hover
  inside a `group`; `tone="light"` for dark backgrounds), `story-marks.tsx` (About page icons).
  All are thin-line inline SVGs. On light backgrounds use the medallion or a dark stroke; the
  bare glyph in `text-taupe` is too faint to read.
- **Catalog**: pages read directly from `auriva-catalog.ts` / `auriva-journal.ts`. Dynamic
  routes resolve data in `loader` and `throw notFound()` for unknown slugs. Each product has a
  `ritual` (the invitation shown in its product page's aura band, `#ritual`) and an optional
  `ritualImage` (that band's background, which should evoke the fragrance; it falls back to the
  category banner).
- **Store** (`auriva-store.ts`): `useAccount()` and `useBag()` subscribe to localStorage via a
  custom `auriva:store` window event plus `storage`. Sign-in just saves `{ name, email }`, and
  checkout simulates a delay and then saves the order. Any real commerce work replaces this module.

## Conventions

- **Imports**: use the `@/` alias for `src/`. Prettier uses double quotes, semicolons, trailing
  commas and 100-column lines.
- **Routes**: `export const Route = createFileRoute("/path")({ head, loader, component })`.
  Every route defines `head()` with a title, description, og:* and twitter:card meta. Each page
  renders `<Nav />` and `<Footer />` itself; there is no shared layout route.
- **Page transitions**: `router.tsx` sets `defaultViewTransition: true` (a 700ms crossfade,
  styled in `styles.css`) and `defaultPreload: "intent"`. Hash links within the same page pass
  `viewTransition: false` plus a smooth `hashScrollIntoView` (see `samePageScroll` in
  `routes/index.tsx`). If a page opens on a photo, await `preloadImage()` (`lib/preload-image.ts`)
  for it in the route `loader` so it doesn't pop in after the fade.
- **About page deep links**: `/about#awaken`, `#aura`, and `#japan` / `#france` / `#india` (the
  sideways-sliding panels in `#align`; on desktop these are invisible anchors at the scroll
  offsets where each panel fills the screen). `useInitialHashScroll` jumps there before first
  paint and `useSectionProgress` snaps its first reading, so pinned sections don't slide into
  place after arriving.
- **Routing**: TanStack conventions only (`$param`, `{-$optional}`, `$.tsx` splat). Don't
  create `src/pages` or Next.js-style layouts. Use `<Link to=...>` for internal navigation.
- **Server-only code**: use `*.server.ts` or `@tanstack/react-start/server-only`, never the
  `server-only` package (ESLint blocks it).
- **Styling**: Tailwind utilities plus brand tokens from `styles.css`. Colors are oklch CSS
  variables exposed as `bg-ivory`, `bg-walnut`/`bg-espresso`, `bg-parchment`, `bg-stone`,
  `bg-sand`, `text-taupe`, etc. New colors go in `:root` and in the `@theme inline` block.
  `--radius` is `0` (square corners everywhere).
  - Custom utilities: `label-track` (small tracked uppercase labels), `hairline`, `reveal`,
    `animate-breathe`, `animate-rise`, `animate-drift`, `tile-pan`, `aura-float`, `hero-smoke*`.
    All animations respect `prefers-reduced-motion`.
  - **Typography voice** (keep every page in sync with the homepage):
    - Headings (`h1`–`h4`) are light (300) and lowercase via a base rule in `styles.css`. Write
      heading text in lowercase anyway, and don't add bold/semibold anywhere.
    - Poetic or editorial lines (italic subtitles, quotes, product poems) are lowercase: add
      `lowercase`. Ordinary paragraphs stay in sentence case.
    - Small labels, eyebrows and CTAs use `label-track` (rendered uppercase). Text links end
      in a single `→` that glides on hover. Buttons are square outlines (or a solid espresso
      fill), never rounded.
    - Section headings are about 30–42px; page titles run larger.
  - Buttons get the hand cursor from a base rule in `styles.css` (Tailwind v4 removed it), so
    don't add `cursor-pointer` to individual buttons.
  - The site font is **Jost** (`font-display` / `font-sans`), loaded from Google Fonts in
    `__root.tsx` as a variable font (weights 200–700, upright and italic). It replaces Nourd,
    the font in the `README.md` brief, which is commercial and not licensed for this project.
  - A `.dark` palette exists (shadcn default) but the site doesn't use dark mode.
- **Design rules** (from the brief): generous whitespace, 0.5–1px lines only, no drop shadows,
  outline or text-with-arrow CTAs, slow 300–500ms ease transitions, and every section stacks
  cleanly on mobile. Check every visual change at phone (375px), tablet (768px) and desktop
  widths.
- **Assets**: import images from `@/assets/*` (they resolve to URLs). `*.asset.json` files point
  at Lovable-hosted copies that 404 on the local dev server, so commit the real file and import
  that instead (the logos are done this way; their `.asset.json` files are now unused).
- **Currency** is INR (₹); prices are plain numbers in the catalog.

## Known issues (pre-existing, not blocking the build)

- `npx tsc --noEmit` reports `TS18046` (`error` is `unknown`) in the `errorComponent`s of
  `journal/$slug.tsx`, `product/$slug.tsx` and `shop/$category.tsx`, and a matching `TS2322` on
  the root `ErrorComponent` in `__root.tsx`. Vite builds regardless.
- `npm run lint` reports 21 Prettier-only formatting errors (all auto-fixable with
  `npx eslint . --fix`) in `Footer.tsx`, `Nav.tsx`, `marks.tsx`, `auriva-journal.ts`, `cart.tsx`,
  `checkout.tsx`, `contact.tsx` and the journal routes, and `styles.css` fails
  `prettier --check`. They date from the Lovable-generated code.
- Fast-refresh warnings: `Reveal.tsx` exports the `useReveal` hook alongside components, and
  several shadcn `ui/` files export variants.
- The `*.asset.json` logo files are unused since the logos were committed as PNGs.

## Backend / environment

- No Supabase, no API calls, no server functions (`createServerFn` unused), no env vars read in
  `src/`. Auth, bag and orders are browser-only (localStorage). The contact form only sets local
  `sent` state, so nothing is actually sent anywhere.
- `.env*` is not committed (`*.local` and `.dev.vars` are gitignored). If you add env vars,
  client-exposed ones must be prefixed `VITE_` and read via `import.meta.env`.
