# Architecture

Auriva is a single TanStack Start app: server-rendered React pages with client-side navigation,
built by Vite and deployed through nitro (Cloudflare by default). There is no backend. All data
is static TypeScript, and "commerce" state lives in the visitor's browser.

## Request lifecycle

```
browser request
  └─ src/server.ts            custom SSR entry (nitro builds from it; see vite.config.ts)
       └─ @tanstack/react-start/server-entry
            └─ src/start.ts   request middleware: errorMiddleware → csrfMiddleware (server fns)
                 └─ router    src/router.tsx → routeTree.gen.ts → src/routes/*
                      └─ __root.tsx shell: <head> (meta, Jost font, styles.css), <Outlet />
```

- **`server.ts`** wraps the whole SSR handler. If rendering throws, or h3 swallows an error into
  a JSON 500 (`{"unhandled":true,"message":"HTTPError"}`), it returns the branded HTML page from
  `lib/error-page.ts` instead.
- **`start.ts`** re-adds TanStack's CSRF middleware (defining the file opts out of the default)
  and a catch-all that turns uncaught errors into the same 500 page.
- **`lib/error-capture.ts`** records the last server error so `server.ts` can log it, and
  **`lib/lovable-error-reporting.ts`** forwards client error-boundary errors to the Lovable editor
  when the site runs inside its preview.

## Routing

File-based (TanStack Router). `routeTree.gen.ts` is generated by the router plugin, so never edit
it. Each route file exports `Route = createFileRoute(path)({ head, loader?, component })`.

| Route                                                                        | File                        | Loader                                                                                                     |
| ---------------------------------------------------------------------------- | --------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `/`                                                                          | `routes/index.tsx`          | none                                                                                                       |
| `/about`                                                                     | `routes/about.tsx`          | none                                                                                                       |
| `/shop`                                                                      | `routes/shop/index.tsx`     | none                                                                                                       |
| `/shop/$category`                                                            | `routes/shop/$category.tsx` | looks up the category (`notFound()` if unknown) and preloads its banner                                    |
| `/product/$slug`                                                             | `routes/product/$slug.tsx`  | looks up the product and category, picks related items, preloads the product photo and the aura-band photo |
| `/journal`                                                                   | `routes/journal/index.tsx`  | none                                                                                                       |
| `/journal/$slug`                                                             | `routes/journal/$slug.tsx`  | looks up the post (`notFound()` if unknown)                                                                |
| `/auth`, `/account`, `/cart`, `/checkout`, `/order-confirmation`, `/contact` | `routes/*.tsx`              | none (read browser state in components)                                                                    |

**Router defaults** (`router.tsx`):

- `defaultViewTransition: true`: every navigation crossfades over 700ms (styled by
  `::view-transition-*` rules in `styles.css`). Browsers without view transitions, and visitors
  with reduced motion, get an instant switch.
- `defaultPreload: "intent"`: hovering or focusing a link runs the destination's loader early.
- `scrollRestoration: true`, with hash links scrolled into view after render.

Loaders `await preloadImage()` (`lib/preload-image.ts`, capped at 1.5s) for the first photo a
page shows, so it's decoded before the crossfade captures the new page and never pops in.

Same-page hash links (homepage "enter the ritual") opt out of the crossfade and scroll smoothly:
see `samePageScroll` in `routes/index.tsx`.

## Data

| Module                  | Holds                                                                                                                                                                                                                                   |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `lib/auriva-catalog.ts` | 3 `categories` and 10 `products` (name, aura, notes, price, images, `ritual` copy, optional `ritualImage`), plus `promises` and lookup helpers `getCategory`, `getProduct`, `productsIn`                                                |
| `lib/auriva-journal.ts` | journal posts (title, excerpt, sections)                                                                                                                                                                                                |
| `lib/auriva-store.ts`   | browser-only commerce: account, bag and last order in `localStorage` (`auriva.account`, `auriva.bag`, `auriva.lastOrder`), with `useAccount()` / `useBag()` hooks kept in sync by a custom `auriva:store` event and the `storage` event |

`AuraName` (softness, grounding, intimacy, balance, stillness, depth, comfort, purity, clarity)
ties products to their glyphs in `components/auriva/aura-marks.tsx`.

Nothing is sent anywhere: sign-in stores a name and email, checkout stores the order, and the
contact and journal "share" forms only flip local component state.

## Build and tooling

- `vite.config.ts` uses `@lovable.dev/vite-tanstack-config`, which already wires TanStack Start,
  React, Tailwind v4, tsconfig paths, nitro, `VITE_*` env injection and the `@` alias. Add extra
  Vite config only through `defineConfig({ vite: { ... } })`.
- TypeScript is strict (`noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`).
- ESLint runs Prettier as a rule; `npm run format` fixes formatting.
- `bun.lock` is the lockfile Lovable uses. `bunfig.toml` blocks packages published less than 24h
  ago.

## Lovable sync

The GitHub repo is connected to Lovable. Commits pushed to `main` appear in the Lovable editor,
and edits made in Lovable are committed to `main`. Never force-push or rewrite pushed history,
and keep `main` building. Lovable-hosted images (`*.asset.json`) don't resolve on a local dev
server, so images are committed as real files under `src/assets/`.
