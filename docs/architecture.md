# Architecture

Auriva is a single TanStack Start app: server-rendered React pages with client-side navigation,
built by Vite and deployed through nitro (Cloudflare by default). There is no backend. All data
is static TypeScript, and "commerce" state lives in the visitor's browser.

## Request lifecycle

```
browser request
  └─ src/server.ts            custom SSR entry (nitro builds from it; see vite.config.ts)
       └─ @tanstack/react-start/server-entry
            └─ src/start.ts   request middleware: errorMiddleware → csrfMiddleware (server fns)
                 └─ router    src/router.tsx → routeTree.gen.ts → src/routes/*
                      └─ __root.tsx shell: <head> (meta, Jost font, styles.css), <Outlet />
```

- **`server.ts`** wraps the whole SSR handler. If rendering throws, or h3 swallows an error into
  a JSON 500 (`{"unhandled":true,"message":"HTTPError"}`), it returns the branded HTML page from
  `lib/error-page.ts` instead.
- **`start.ts`** re-adds TanStack's CSRF middleware (defining the file opts out of the default)
  and a catch-all that turns uncaught errors into the same 500 page.
- **`lib/error-capture.ts`** records the last server error so `server.ts` can log it. Client
  render errors are logged to the console by the root error boundary.

## Routing

File-based (TanStack Router). `routeTree.gen.ts` is generated by the router plugin, so never edit
it. Each route file exports `Route = createFileRoute(path)({ head, loader?, component })`.

| Route                                                                        | File                        | Loader                                                                                |
| ---------------------------------------------------------------------------- | --------------------------- | ------------------------------------------------------------------------------------- |
| `/`                                                                          | `routes/index.tsx`          | `getProducts({ featured: "bestseller" })` (failure just hides that section)           |
| `/about`                                                                     | `routes/about.tsx`          | none                                                                                  |
| `/shop`                                                                      | `routes/shop/index.tsx`     | `getCategories()`                                                                     |
| `/shop/$category`                                                            | `routes/shop/$category.tsx` | `getCategoryPage` + `getCategories` (`notFound()` if unknown), preloads the banner    |
| `/product/$slug`                                                             | `routes/product/$slug.tsx`  | `getProductPage` (`notFound()` if unknown), preloads the product and aura-band photos |
| `/journal`                                                                   | `routes/journal/index.tsx`  | `getJournalPosts()`                                                                   |
| `/journal/$slug`                                                             | `routes/journal/$slug.tsx`  | `getJournalPostPage` (`notFound()` if unknown)                                        |
| `/auth`, `/account`, `/cart`, `/checkout`, `/order-confirmation`, `/contact` | `routes/*.tsx`              | none: visitor state comes from `lib/api/hooks.ts` in the browser                      |

**Router defaults** (`router.tsx`):

- `defaultViewTransition: true`: every navigation crossfades over 700ms (styled by
  `::view-transition-*` rules in `styles.css`). Browsers without view transitions, and visitors
  with reduced motion, get an instant switch.
- `defaultPreload: "intent"`: hovering or focusing a link runs the destination's loader early.
- `scrollRestoration: true`, with hash links scrolled into view after render.

Loaders `await preloadImage()` (`lib/preload-image.ts`, capped at 1.5s) for the first photo a
page shows, so it's decoded before the crossfade captures the new page and never pops in.

Same-page hash links (homepage "enter the ritual") opt out of the crossfade and scroll smoothly:
see `samePageScroll` in `routes/index.tsx`.

## Data

All data goes through `src/lib/api/`, the seam between this frontend and the separately built
backend. The endpoints, payloads and errors are specified in `backend-handoff.md`.

```
page / loader ──▶ lib/api/index.ts ──VITE_API_URL set──▶ client.ts ──fetch──▶ backend
                        │                                  (JSON, cookies, ApiError)
                        └──unset──▶ mock.ts (catalog + journal from code; account, bag,
                                             orders in localStorage)
components ──▶ lib/api/hooks.ts (TanStack Query: useUser, useCart, mutations) ──▶ index.ts
```

| Module                  | Holds                                                                                                                       |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `lib/api/index.ts`      | one async function per endpoint (catalog, journal, auth, bag, orders, forms)                                                |
| `lib/api/client.ts`     | `request()` (base URL, `credentials: "include"`, JSON), `ApiError`, `errorMessage()`, `usingMockApi`                        |
| `lib/api/types.ts`      | shared shapes: `User`, `Cart`, `Address`, `Order`, page payloads, form inputs                                               |
| `lib/api/hooks.ts`      | TanStack Query hooks and mutations for the visitor's account, bag and orders                                                |
| `lib/api/mock.ts`       | in-browser implementation used until the backend exists (localStorage keys `auriva.account`, `auriva.bag`, `auriva.orders`) |
| `lib/auriva-catalog.ts` | 3 `categories` and 10 `products` (the mock's data and the seed for the backend), plus the static `promises` copy            |
| `lib/auriva-journal.ts` | journal posts (the mock's data and the seed for the backend)                                                                |

The `QueryClient` in `router.tsx` doesn't retry 4xx errors (e.g. 401 when signed out), retries
other failures once, and treats data as fresh for 30s.

`AuraName` (softness, grounding, intimacy, balance, stillness, depth, comfort, purity, clarity)
ties products to their glyphs in `components/auriva/aura-marks.tsx`.

Google sign-in (`lib/google-auth.ts`) loads Google's script only on `/auth`. The button returns
an ID token that `api.signInWithGoogle` sends to the backend to verify (the mock only decodes and
sanity-checks it). See `google-sign-in.md`.

## Build and tooling

- `vite.config.ts` uses `@lovable.dev/vite-tanstack-config` (an npm package left from the
  project's Lovable start), which wires TanStack Start, React, Tailwind v4, tsconfig paths, nitro,
  `VITE_*` env injection and the `@` alias. Add extra Vite config only through
  `defineConfig({ vite: { ... } })`.
- TypeScript is strict (`noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`).
- ESLint runs Prettier as a rule; `npm run format` fixes formatting.
- npm with `package-lock.json`; `npm ci` for clean installs.

## History

The project started in Lovable and moved to Claude Code-only development in October 2026. The
Lovable sync, its bun lockfile, its editor error reporting and the Lovable-hosted asset links
were removed. The live site at `auriva-essence-studio.lovable.app` is Lovable-hosted, so new
hosting is needed for changes to go live.
